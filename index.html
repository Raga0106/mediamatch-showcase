01 / THE PROBLEM

網路上不缺資訊。
缺的是找到它們的方法。

我們每天在不同平台間切換，真正值得看的內容卻常常被熱門話題、重複推薦和資訊噪音淹沒。

PROBLEM / 01

內容散落各處

教學在 YouTube、深入分析在部落格、觀點在社群。想追蹤一個主題，卻得管理一堆 App。

PROBLEM / 02

演算法不受控制

平台越來越了解你會點什麼，卻不一定知道你真正想學什麼，更難讓你直接調整推薦方向。

PROBLEM / 03

好內容很難被發現

在認識優質創作者之前，你不知道該搜尋哪些名字。搜尋與訂閱需要時間，探索往往就此停止。

如果發現好內容，不必從「知道誰值得追」開始呢？

只要告訴系統什麼吸引你，讓推薦逐漸成為你的知識雷達。

02 / THE IDEA

把找知識這件事，
變得像配對一樣直覺。

不是要你再經營一個平台，而是讓「找到、判斷、收藏」變成一個自然的流程。

STEP 01

選擇興趣

挑主題、平台、語言和內容形式。不必先知道有哪些創作者。

STEP 02

快速配對

右滑喜歡、左滑略過，也可以收藏，或明確表示不感興趣。

STEP 03

調整推薦

主題、深度與探索比例可見、可調，不被困在黑盒演算法裡。

STEP 04

帶走發現

收藏內容、發現新來源，再回原平台閱讀或觀看完整內容。

04 / WHAT MAKES IT DIFFERENT

不是把所有 Feed
塞進同一個畫面。

跨平台整合只是基礎。真正想解決的是：讓使用者更容易發現未知的好內容，而且知道推薦為什麼出現。

不只推薦你喜歡的。
也推薦你還不知道自己會喜歡的。

演算法保留探索空間，避免一味推送相似主題，讓知識邊界持續擴張。

先做對一件事。
然後把它做大。

這是計畫中的開發階段，不是假裝已經完成的功能清單。每個階段都應該能展示、測試、驗證。

PHASE 01優先製作 · MVP

知識內容探索

  • 主題偏好與滑動卡片
  • RSS / YouTube 內容池
  • 推薦排序與收藏
  • 可解釋興趣輪廓
PHASE 02推薦品質升級

更懂你的推薦

從手動標籤與簡單排序，逐步擴充內容理解和推薦品質。

  • 語意向量與相似度
  • 更多來源、搜尋與篩選
  • 探索模式與推薦多樣性
  • 真實使用者回饋分析
PHASE 03長期願景

從資訊到人與社群

擴展到全類型內容，讓使用者能分享自己的品味，探索不同的人。

  • 生活、娛樂等更多內容類型
  • 可分享的主題清單

  • 尊重隱私的興趣配對
✳初期成功標準不是「滑得多」，而是「使用者能否找到原本不知道、卻願意持續關注的好來源」。

09 / FAQ

你可能還想知道。

現在產品已經開發到哪裡？

目前是產品構想與功能規劃階段。這個網頁裡的配對卡片是能操作的前端概念 Demo，用來說明互動方式；尚不是已串接真實內容及推薦後端的完整產品。

這跟 YouTube、Feedly 或一般 RSS 閱讀器有什麼不同？

重點不是再聚合一份內容清單，而是讓使用者從不認識來源的狀態開始，透過快速互動找出喜歡的內容與創作者，並且可以理解、修改推薦方向。

可以免費開發嗎？會不會一直需要付 AI API 費用？

初期以免費／開源技術、基本標籤推薦和小型內容池為主，不必在每次滑動時呼叫大型付費模型。正式部署仍可能產生主機、資料庫或外部 API 成本，會依需求逐步評估。

Instagram、TikTok 之類的平台也能直接抓內容嗎？

不同平台對第三方資料存取、嵌入及商業使用有不同限制。我們會優先使用官方 API、RSS、合法公開資料或使用者主動提供的連結，不把違反平台規範的爬蟲當成首版基礎。

不是工程師也可以加入嗎？

可以。產品訪談、內容來源策展、資訊架構、UI・UX 設計、使用者測試，以及介紹給適合的開發夥伴，都可能是有價值的貢獻。實際合作方式由成員共同討論。
