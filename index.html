01 / THE PROBLEM

網路上不缺資訊。
缺的是找到它們的方法。

我們每天在不同平台間切換，真正值得看的內容卻常常被熱門話題、重複推薦和資訊噪音淹沒。

PROBLEM / 01

內容散落各處

教學在 YouTube、深入分析在部落格、觀點在社群。想追蹤一個主題，卻得管理一堆 App。

PROBLEM / 02

演算法不受控制

平台越來越了解你會點什麼，卻不一定知道你真正想學什麼，更難讓你直接調整推薦方向。

PROBLEM / 03

同個主題，該追誰？

同樣談 AI，有人做技術實測，有人整理新聞。只知道分類還不夠，你需要找到符合自己深度與風格的來源。

找到你想學的事，也找到願意持續關注的人。

把「主題興趣」「創作者風格」「單篇收穫」分開理解，讓推薦逐漸認識你的資訊品味。

02 / THE IDEA

把找知識這件事，
變得像配對一樣直覺。

內容配對與創作者探索，是兩個互相連接的入口。從一篇作品認識來源，也能先找人，再看代表作品。

STEP 01

表達需求

選擇想探索的主題，再設定平台、語言等條件。興趣與硬性篩選各自處理。

STEP 02

快速配對

右滑喜歡、左滑略過，也可以收藏，或明確表示不感興趣。

STEP 03

認識創作者

看內容風格、代表作品和個人偏好，再決定是否加入你的追蹤清單。

STEP 04

讀完，再回饋

收藏後回原平台閱讀。讀後告訴系統有沒有收穫，逐步建立自己的資訊圈。

03 / INTERACTIVE PROTOTYPE

04 / CREATOR DISCOVERY

同樣聊 AI，
你想持續聽誰說？

分類只是起點。有人擅長實測，有人擅長快速整理；用代表作品認識風格，找到在這個主題裡對你有價值的來源。

01 / TOPIC

你想知道什麼？

人工智慧、工程實作、商業金融……先找到有興趣的領域。

02 / CREATOR

你欣賞誰的方式？

同個領域中，分開理解你對各位創作者的深度、表達與內容風格的偏好。

03 / CONTENT

這篇真的有收穫嗎？

追蹤作者不代表喜歡他的每篇作品。讀後回饋只描述你的收穫，不替內容做真偽認證。

05 / VALUE & TRUST

對我有用，
也要知道有沒有根據。

個人收穫與內容可信度，需要不同的證據。偏好分數用來幫你找來源；判斷內容是否可信，仍要看原始資料、引用與查核。

「有收穫」是你的體驗。
可信度需要可查證的證據。

不把粉絲數、點擊或喜歡直接當作內容品質，也不把個人偏好包裝成作者的客觀排名。

11 / FAQ

你可能還想知道。

現在產品已經開發到哪裡？

目前是產品構想展示與可操作的前端 Demo。內容配對、創作者篩選、追蹤和讀後回饋都使用虛構資料，操作僅保留在本次頁面，重新整理即重設；尚未串接真實來源、使用者帳號、資料庫或正式推薦後端。

這跟 YouTube、Feedly 或一般 RSS 閱讀器有什麼不同？

希望從「我不知道該追誰」的問題出發：同一主題下，分別理解你喜歡哪些創作者、哪些作品與表達風格。再用追蹤管理長期來源，並透過單篇讀後回饋持續調整。

追蹤會直接訂閱我的 YouTube 帳號嗎？

MediaMatch 內追蹤，是將來源加入自己的資訊圈。它和外部平台的訂閱分開；正式版初期會提供前往原平台的連結，不會假設能替你操作第三方帳號。本頁的追蹤僅為虛構示範。

個人偏好分數代表作者有多專業、內容有多可信嗎？

分數僅示意這位創作者在該主題下與你的偏好是否相合。讀後「有收穫／普通／偏水」描述個人體驗，不是客觀品質、專業能力或真偽評分；可信度仍需要引用、原始資料與查核等證據。

可以免費開發嗎？會不會一直需要付 AI API 費用？

初期以免費／開源技術、基本標籤推薦和小型內容池為主，不必在每次滑動時呼叫大型付費模型。正式部署仍可能產生主機、資料庫或外部 API 成本，會依需求逐步評估。

Instagram、TikTok 之類的平台也能直接抓內容嗎？

不同平台對第三方資料存取、嵌入及商業使用有不同限制。我們會優先使用官方 API、RSS、合法公開資料或使用者主動提供的連結，不把違反平台規範的爬蟲當成首版基礎。

不是工程師也可以加入嗎？

可以。產品訪談、內容來源策展、資訊架構、UI・UX 設計、使用者測試，以及介紹給適合的開發夥伴，都可能是有價值的貢獻。實際合作方式由成員共同討論。
